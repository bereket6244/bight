# Engine source correspondence

GPLv3 §6 requires that whoever receives the binary can obtain its source. This
file identifies exactly which engine binary Bight distributes, so that the
source corresponding to *that binary* — not merely to some version of
Stockfish — can be found.

## What ships

Two files, in `public/engine/`, copied into `dist/engine/` by Vite and into
`assets/public/engine/` in the APK by Capacitor:

| File | Bytes | SHA-256 |
| --- | --- | --- |
| `stockfish-18-lite-single.js` | 21,429 | `5243fd9b276cab7dfe3ad1d43ab9ead73568fac76468c614242977a210c4a391` |
| `stockfish-18-lite-single.wasm` | 7,295,411 | `a8fbc05ec6920b56d7485826dcb02c5ffd2826bcbf751cf973046f237a9096f1` |

`public/engine/COPYING-stockfish.txt` (35,821 bytes) is the GPLv3 text, copied
alongside so the licence travels with the binary. `public/engine/manifest.json`
records the same checksums and is regenerated by the copy script.

These checksums are also asserted by `scripts/prepare-engine.mjs`, which
refuses to run if the files in `node_modules` differ from what it copied.

### On the precision of "Stockfish 18"

The npm package identifies the upstream engine by release line, not by commit.
The published tarball does not contain a Stockfish commit hash, and the built
`.wasm` does not report one over UCI. So the honest statement is: **this binary
was built by the Stockfish.js project from the Stockfish 18 line, and the exact
upstream commit is whatever `nmrugg/stockfish.js` used when tagging its own
`v18.0.8`.** That tag is the durable pointer, and it is recorded here rather
than a guessed commit hash.

Anyone needing the precise upstream commit should read it from the
`stockfish.js` repository at tag `v18.0.8`, which pins its Stockfish submodule.

## Modifications

**None.** The files are copied byte-for-byte out of the npm package by
`scripts/prepare-engine.mjs`; the checksums above are the checksums of the
files inside the published tarball. Nothing is patched, minified, re-bundled or
otherwise altered, so there are no local modifications to publish as source.

## Which build, and why

The package ships five flavours. Bight uses the **lite single-threaded
WebAssembly** build.

| Flavour | Size | Why not |
| --- | --- | --- |
| Full multi-threaded | ~113 MB wasm | Far too large for an APK, and needs cross-origin isolation. |
| Full single-threaded | ~113 MB wasm | Far too large for an APK. |
| Lite multi-threaded | ~7 MB wasm | Needs cross-origin isolation (COOP/COEP), which a Capacitor WebView does not provide. |
| **Lite single-threaded** | **~7 MB wasm** | **Chosen.** Runs without special headers, and is far stronger than any human. |
| ASM.js | ~10 MB js | Larger than the lite WASM builds and much slower. Not included. |

The package's own documentation recommends the lite single-threaded build for
ordinary browser applications, for these reasons.

## Reproducing the shipped files

```bash
npm ci                              # installs stockfish@18.0.8 from the lockfile
node scripts/prepare-engine.mjs     # copies the two files into public/engine
npm run build                       # Vite copies public/ into dist/
npx cap sync android                # Capacitor copies dist/ into the APK assets
node scripts/build-apk.mjs          # assembles the APK
node scripts/inspect-apk.mjs        # asserts the engine assets are inside it
```

To verify independently, without trusting this repository:

```bash
npm pack stockfish@18.0.8
tar -xzf stockfish-18.0.8.tgz
sha256sum package/bin/stockfish-18-lite-single.{js,wasm}
```

The two checksums must match the table above.

## Rebuilding the engine from source

Only necessary to change the engine itself. Per the Stockfish.js README:

```bash
git clone https://github.com/nmrugg/stockfish.js
cd stockfish.js
git checkout v18.0.8
# Requires emscripten 3.1.7 on the PATH
./build.js --single-threaded --lite -f
```

A rebuild is not expected to be bit-identical: Emscripten output depends on the
toolchain version and build environment. The checksums above identify the
binary that was *distributed*, which is what the source-correspondence
obligation is about.
